# ModelRotator

将一个虚拟模型映射到有序实际模型目标；实际模型调用失败时由插件内部有限轮转，成功后保持 sticky 目标或按配置优先级选择。手动激活只更新后续请求使用的 pin，不会关闭、重置或重放已经开始的连接。

## 功能

- 兼容 JS 版插件文档 v3：虚拟模型路由、故障/超时计数、健康状态、active pin、31 天 Token 用量（保留旧版紧凑数组行）。配置保存到插件 Custom Credential；仅读取到缺失配置时建立默认账户，读错误/损坏 JSON 不会覆盖现有配置。
- 支持 `/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/responses`、`/v1/messages`。保留原始请求字段，仅替换实际模型并移除宿主内部路由字段。
- 最多尝试 5 个实际模型；客户端输入错误不增加故障计数，平台共享认证错误不会继续轮转。流式响应采用原始流透传，连接一旦开始由宿主生命周期负责，不做中途重试。
- 可配置降级：全局 `demoteThreshold`（失败降级阈值，1–100，默认 1）控制后续请求排序。普通失败与超时分别计数，任一桶达到阈值后将目标排到队尾，组内保留原优先级；sticky 活跃位同样遵循此阈值。旧配置未提供该字段时保持首次失败即降级的行为。对已经等满超时的目标，下一次只给 20 秒复检窗口（配置更短时按配置）；超时不再上调首字节观测值。
- 定时探测已禁用或计数未清零的实际模型，可手动探测；支持按日查看 Token 用量。
- 探测的单目标超时可在设置里配置（5–180 秒，默认 45 秒），超时与“仅返回空内容”分别归类，不再用固定的 12 秒把慢目标误判为异常。
- 内嵌管理页面支持新增/编辑/排序虚拟模型目标、启停路由、手动切换当前 pin、平台回环/API Key 与等待预算设置。已选实际模型可按住行首 ⋮⋮ 拖动排序（蓝线标示插入位置），也可用上移/下移按钮或聚焦行后按 Alt+↑/↓；放下后更新待保存顺序，取消拖动保持原顺序，点击“保存虚拟模型”后才生效。

- 路由管理使用紧凑网格卡片：收起时显示当前目标与分段健康条，展开查看候选状态和手动切换；支持按模型搜索、状态筛选及浅色/暗色模式。用量统计独立为页签，首次打开时读取数据。

## 失败、降级与禁用

单次请求在响应开始前遇到可轮转错误会立即尝试下一候选目标（最多 5 个），不等待降级或禁用阈值。流已经开始后不重试；`streamIdleSeconds` 只控制流连续无数据时的中断等待，不增加响应开始前的故障计数。

`demoteThreshold` 控制之后请求的候选顺序；例如设为 3，目标失败 1–2 次仍保留原优先级，第 3 次后排到队尾。失败与超时分别比较，不相加。`prefer-highest` 按降级后的优先级取候选；sticky 在原活跃目标未禁用且未降级时保持它。成功请求或有效探测成功会同时清除两类计数。

路由的 `failureThreshold` 独立控制禁用：普通失败达到该值，或超时达到 `max(failureThreshold × 2, 4)` 后禁用目标。把降级阈值设为普通失败禁用阈值，可以让普通失败一直保留优先级直至禁用；超时仍按它自己的禁用阈值处理。降级阈值是全局值，不随各路由禁用阈值自动变化。

## 手动切换语义

管理页面选择“当前活跃目标”后，插件原子更新配置中的 active pin。已进入宿主并开始向上游请求的连接继续由原有请求使用它已经选中的目标；不会断连、取消或切换该连接。pin 从后续新进入的请求开始生效。恢复自动选择会清除 pin，按健康状态和目标顺序重新选路。

## 探测语义

探测对每个目标发一条极小请求（生成类端点的输出预算为 1 token，embeddings 使用短文本输入），用于判断目标当前是否可用。

- **单目标超时**：设置项“单目标探测超时”，默认 45 秒，范围 5–180 秒。免费上游首字节常在 40–60 秒，12 秒级的固定超时会把慢但可用的目标误判为异常，所以这里按可配置值等待。
- **并发**：手动探测并发 4，避免一次性打爆同一批免费上游（并发越高，越容易互相拖慢并集体超时）；定时探测针对已禁用目标，以及启用路由中计数未清零的目标（包含未达到降级阈值的目标），并发 8。
- **总预算**：手动探测 = 批次数 × 单目标超时 + 15 秒（20–300 秒封顶）；定时任务 = 240 秒。预算用尽时返回已完成的结果并标记 `remaining`，可再点一次继续。
- **结果分类**：`正常`、`结果不确定`（命中已应答但没有正文的错误特征时，不解除禁用、不清计数）、`超时`（单目标超时）、`异常`（其他非 2xx 或错误）。探测失败与超时只返回探测结果，不增加业务请求的失败或超时计数。

## 管理与安全

管理端点通过宿主默认 AdminSession 认证，页面经 `window.Router2API.request` 调用相对路由。平台 Base URL 仅允许本机回环地址，避免把此代理能力变成任意 URL 请求；平台 API Key 写入插件配置，已认证管理设置接口仍返回完整值供排障，管理页面仅显示掩码；不要共享包含密钥的设置接口响应。

插件 Key / 平台名为 `modelrotator`。来自 JS 版的 `js-model-rotator` 配置记录只在宿主按当前插件 Key 提供旧账户时自动读取；如果宿主对账号按 PluginKey 隔离，须在宿主迁移数据时复制旧 Credential 到新插件账户空间，不能由公开插件绕过宿主账号边界。

## 版本号

版本号只有一个来源：`Plugins.ModelRotator.csproj` 的 `<Version>`。宿主管理页显示的是入口 DLL 的程序集版本（`assembly.GetName().Version`），`build.ps1` 也把同一个程序集版本写进发行包 `plugin.json`，所以两者天然一致。手工打包时不要另写版本号，也不要只改 `plugin.json`——只改清单会让页面继续显示旧版本，看起来像升级没生效。

## 构建与测试

从仓库根目录运行：

```powershell
dotnet build ./src/Plugins.ModelRotator/Plugins.ModelRotator.csproj --disable-build-servers -m:1 -p:ConcurrentBuild=false -p:UseSharedCompilation=false
dotnet test ./tests/Router.Tests/Router.Tests.csproj --disable-build-servers -m:1 -p:ConcurrentBuild=false -p:UseSharedCompilation=false
```

页面验收需要 Node.js 20+，从仓库根目录运行：

```bash
npm install --prefix tests/browser
npm --prefix tests/browser run install:browser
npm --prefix tests/browser test
```

脚本从实际 C# 页面源码提取 HTML，在无同源权限的 sandbox iframe 中模拟宿主请求桥；覆盖折叠卡片、搜索筛选、目标切换、编辑排序与取消、日期显隐、错误恢复、密钥掩码、390px 布局和暗色截图。仅使用虚构数据，禁止真实网络请求；结果和截图输出到忽略的 `artifacts/modelrotator-ui/`。这不替代真实宿主集成验证。已有 Chromium 可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定，受限容器需要时可设置 `PLAYWRIGHT_NO_SANDBOX=1`。
